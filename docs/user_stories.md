# User Stories and Acceptance Criteria

## Executive
- As an executive, I want revenue and cloud cost on the same trend so that I can detect margin compression.
  - Acceptance: MRR, cloud cost, cost ratio, gross margin, and budget variance are visible for the selected time range.

## Product
- As a product leader, I want to compare feature adoption with cost per active user so that I can prioritize investment.
  - Acceptance: each feature has adoption, direct cost, unit cost, growth, and an explainable quadrant.

## Finance / FinOps
- As a finance partner, I want cost by AWS service and environment so that I can identify savings opportunities.
  - Acceptance: service, environment, category, budget, and anomaly views can be filtered and downloaded.

## Customer Success
- As a CSM, I want accounts with high cost-to-revenue ratios so that I can target pricing or adoption conversations.
  - Acceptance: account table contains MRR, cost, ratio, margin, health, risk tier, and owner.

## Engineering
- As a cloud operator, I want incident and cost anomaly evidence so that I can distinguish product growth from operational waste.
  - Acceptance: incidents, downtime, anomalies, and service cost are visible together.

## Analyst
- As an analyst, I want KPI definitions and lineage so that I can validate that stakeholders use consistent logic.
  - Acceptance: data dictionary, KPI dictionary, quality report, and architecture are documented.

## Portfolio reviewer
- As an interviewer, I want a reproducible repository so that I can assess technical execution and business judgment.
  - Acceptance: setup, tests, data regeneration, deployment, limitations, findings, and interview story are included.
